# Captionor 작업 지침

이 저장소를 수정하는 에이전트는 작업 전에 이 파일과 `README.md`,
`captionor_config.json`을 읽고 현재 동작을 확인한다. 원본 ComfyUI 흐름을
확인해야 할 때는 `자연어 캡션 뉴뉴 수정.json`을 참고한다.

## 핵심 동작

- 이 프로그램은 ComfyUI 없이 OpenAI 호환 비전 API를 호출하는 Python CLI다.
- 입력 태그 `.txt`는 읽기 전용이다. 크기가 2KB를 넘어도 수정하거나
  재생성하거나 백업하지 않는다.
- API 요청에는 system prompt, 전처리한 이미지, 기존 입력 태그를 이 순서로
  유지한다.
- 크기 제한은 Gemma가 생성한 자연어 캡션에만 적용한다. 캡션과 마지막
  줄바꿈을 UTF-8로 인코딩한 저장 크기가 정확히 2,048바이트면 허용하고,
  2,049바이트부터 새 캡션을 요청한다.
- 캡션 길이 초과 재생성 횟수인 `caption.max_attempts`와 전송 오류 재시도
  횟수인 `api.max_retries`는 서로 다른 설정이다.
- 길이 재요청에서도 이미지, system prompt, 입력 태그는 유지한다. 고정된
  결과가 반복되지 않도록 후속 요청의 seed와 짧게 생성하라는 지시만 바꾼다.
- 크기 검사를 통과한 캡션이 생긴 뒤에만 결과 파일을 원자적으로 저장한다.
  모든 시도가 실패하면 `--overwrite` 상태에서도 기존 캡션을 보존한다.
- 각 항목의 현재 태그, Gemma 캡션 응답과 바이트 크기, 진행률, 경과 시간,
  예상 총 시간과 예상 남은 시간을 터미널에 표시한다.

## 이미지와 경로

- EXIF 방향을 보정하고 RGB로 변환한 뒤 설정에 따라 리사이즈하여 PNG data
  URL로 API에 전달한다.
- JPEG XL은 `pillow-jxl-plugin`으로 처리한다. 디코더가 없거나 파일이
  손상된 경우에는 사용자가 조치할 수 있는 오류를 유지한다.
- 입력 이미지, 입력 태그, 출력 캡션이 서로 덮어쓰이지 않도록 기존 경로
  충돌 검사를 보존한다.
- 같은 stem의 여러 이미지는 읽기 전용 입력 태그 하나를 공유할 수 있다.

## 변경 원칙

- ComfyUI 런타임 의존성을 다시 추가하지 않는다.
- 기존 설정이나 요청 본문을 바꿀 때는 원본 워크플로와 현재 코드에서 실제로
  사용되는 값을 먼저 확인한다.
- 사용자 파일을 직접 덮어쓰는 새 동작은 피하고, 출력은 임시 파일과
  `os.replace()`를 사용하는 원자 저장 방식을 유지한다.
- 동작이나 설정이 바뀌면 `README.md`, `captionor_config.json`, 테스트를 함께
  갱신한다.
- JXL을 포함한 지원 확장자와 의존성 문서를 코드와 일치시킨다.

## 필수 검증

변경 후 가능한 범위에서 다음 검사를 실행한다.

```bash
python3 -m py_compile captionor.py tests/test_captionor.py
python3 -m json.tool captionor_config.json
python3 -m unittest discover -s tests -v -b
git diff --check
```

캡션 크기 관련 변경에는 최소한 다음 경우를 검증한다.

- UTF-8 저장 크기 2,048바이트는 한 번에 저장된다.
- 2,049바이트부터 같은 이미지와 태그로 다시 요청한다.
- 한글 같은 다중 바이트 문자도 문자 수가 아닌 UTF-8 바이트로 판정한다.
- 모든 생성 시도나 후속 API 호출이 실패하면 새 파일을 저장하지 않고 기존
  캡션과 입력 태그를 보존한다.
